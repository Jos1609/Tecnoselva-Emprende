# Instrucciones del proyecto

## Calidad y coherencia de los entregables

- Crear siempre contenido, código, documentación y propuestas con calidad profesional; evitar soluciones básicas, genéricas o meramente demostrativas.
- El código debe ser funcional, coherente con el proyecto y suficientemente completo para que pueda ser compilado y probado por el usuario.
- No ejecutar compilaciones, builds ni tareas equivalentes automáticamente; el usuario se encargará de compilar el proyecto.
- Antes de crear o modificar algo, revisar la estructura, patrones, convenciones visuales, arquitectura y nivel de detalle ya existentes en el proyecto.
- Mantener coherencia con los elementos existentes: nombres, organización, estilos, componentes, flujos, validaciones y criterios de diseño.
- Cuando una solución nueva pueda integrarse mejor con patrones existentes, reutilizarlos en lugar de introducir alternativas inconsistentes.
- Entregar resultados completos, pulidos y listos para uso real, incluyendo los detalles necesarios de UX, accesibilidad, robustez, mantenibilidad y manejo de errores según corresponda.
- Si existen varias opciones razonables, elegir la que mejor preserve la calidad y la coherencia global del proyecto, explicando brevemente cualquier decisión relevante.
